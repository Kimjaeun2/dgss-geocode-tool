# 방제지리정보 주소 지오코딩 도구 (정적 파일 버전)

Java, Maven, 빌드 과정이 전혀 필요 없습니다. `index.html`, `app.js`, `style.css`
3개 파일이 전부입니다. 지오코딩 로직은 전부 브라우저(자바스크립트)에서 돌아가고,
엑셀 데이터도 서버로 전송되지 않습니다.

## ⚠️ 주의: 파일을 더블클릭해서 바로 열면 안 됩니다

`index.html`을 더블클릭해서 `file://` 방식으로 열면 카카오맵이 뜨지 않습니다.
카카오 지도 API는 `http://` 또는 `https://` 주소로 접속했을 때만 동작하도록
도메인 검증을 하기 때문입니다. 그래서 이 파일들을 "웹으로" 열어주는 최소한의
방법이 하나는 필요합니다. 아래 3가지 중 하나를 상황에 맞게 고르시면 됩니다.

---

## 방법 A. 사내에 이미 떠 있는 웹서버가 있는 경우 (가장 추천)

지금 방역시스템이 돌아가는 톰캣이든, 다른 사내 웹서버든 상관없습니다.
**빌드 없이 이 3개 파일을 그 서버의 정적 파일 폴더에 그냥 복사**하면 끝입니다.

- 예: 톰캣이면 `webapps/geocode/` 폴더를 새로 만들고 그 안에 3개 파일 복사
  → 팀원들은 `http://서버주소:포트/geocode/index.html` 로 접속
- 기존 시스템과 완전히 분리된 별도 경로이므로 기존 코드/배포에 영향 없습니다.

## 방법 B. 무료 정적 호스팅 사용 (설치 전혀 없이 URL 하나로 끝)

GitHub Pages 같은 무료 정적 호스팅에 이 3개 파일만 올리면, 어떤 서버도 직접
운영할 필요 없이 고정된 URL 하나가 생깁니다. 팀원들은 그 URL만 북마크해두면
됩니다. (엑셀 데이터는 브라우저 안에서만 처리되고 어디로도 전송되지 않으니
데이터 유출 걱정 없이 써도 되는 구조입니다. 다만 사내 보안 정책상 외부 서비스
사용이 금지되어 있는지는 확인이 필요합니다.)

간단 절차:
1. github.com 가입 → 새 저장소(repository) 생성
2. 이 3개 파일 업로드
3. 저장소 Settings → Pages → 배포 활성화
4. 발급되는 주소(예: `https://아이디.github.io/저장소명/`)로 팀원들 접속

## 방법 C. 임시로 본인 PC에서만 띄워보고 싶을 때 (테스트용)

윈도우에 파이썬이 설치되어 있다면(`python --version`으로 확인), 이 폴더에서
명령 프롬프트를 열고 아래 한 줄만 실행하면 됩니다. 설치나 빌드가 전혀 없습니다.

```
python -m http.server 8090
```

그 다음 `http://본인PC의사내IP:8090` 으로 다른 팀원들이 접속 가능합니다.
단, 이 명령을 실행한 창을 닫으면 접속이 끊기고, 파이썬이 없으면 이 방법은
바로 안 되니 A 또는 B를 권장합니다.

---

## 카카오 JS 키 설정은 동일하게 필요합니다

`index.html` 안의 `KAKAO_JS_KEY` 부분을 발급받은 키로 교체하고, 카카오
디벨로퍼스 플랫폼 설정에 실제 접속 주소(위 A/B/C 중 선택한 최종 URL)를
등록해야 지도가 뜹니다. (이 부분은 이전 안내와 동일합니다.)

## 좌표계 변환

- 카카오 API는 좌표를 WGS84 경위도로 반환합니다. 기존 시트의 x, y 컬럼은 투영좌표계(미터)이므로, 이 도구는 선택한 좌표계로 변환한 값을 x, y에 저장합니다.
- **이 시스템이 실제로 쓰는 좌표계는 EPSG:2097 입니다 (기본값).** 5181 / 5174 / 2097 은 서로 수백 m 어긋나므로, 다른 좌표계로 잘못 고르면 신규 등록분만 밀려서 들어갑니다. 확신이 안 서면 "2-1. 좌표계 확인" 단계의 [기존 좌표로 자동 판정]으로 다시 확인하세요.
- 주소검색으로 안 되는 지명형(공원, 하천, 마을 등)은 자동으로 장소검색으로 재시도합니다. 결과가 1건이면 자동 채택하고, 여러 건이면 보정 목록으로 넘겨 직접 고르게 합니다.
- 지번주소가 있으면 지번주소를 우선 사용하고, 없을 때만 도로명주소를 사용합니다.
- 이미 x, y 값이 채워진 행은 API 호출 없이 원래 값을 그대로 유지합니다 (좌표계 변환도 적용하지 않음).
- 업로드한 엑셀은 브라우저 메모리에서만 처리되고 서버로 전송되지 않습니다.

## 결과 컬럼

기존 수작업 `_작업` 시트와 컬럼 구조가 동일하도록 맞춰져 있습니다. `_완료` 시트에는 원본 주소 컬럼 바로 뒤에 아래 컬럼이 순서대로 삽입됩니다.

| 컬럼 | 내용 |
|---|---|
| `소재지` | 지번주소 우선, 없으면 도로명주소 |
| `locx` | 예전 시트에 있던 빈 컬럼. 자리만 맞추고 값은 쓰지 않습니다 |
| `지오코딩 안된 주소 보충` | 지명형 주소가 다른 실제 주소로 치환된 경우에만 채워지는 대체주소 (검색 쿼리가 아니라 실제 확정된 주소입니다) |
| `x` / `y` | 확정 좌표 (EPSG:2097) |
| `지번` / `도로명` | API가 돌려준 실제 주소 |

`매칭방식`·`검색어`·`경도(WGS84)`·`위도(WGS84)` 같은 추가 추적용 컬럼은 만들지 않습니다 — `_작업` 시트와 완전히 같은 구조를 유지하기 위함입니다.

## 처리 속도

- 여러 건을 동시에 처리합니다. "동시 처리 수"는 기본 6이며, 오류가 자주 나면 3이나 1로 낮추세요.
- 번지·건물번호가 없는 지명형 주소(공원, 하천, 마을 등)는 주소검색이 반드시 실패하므로 곧바로 장소검색으로 보내 불필요한 호출을 줄입니다.
- 같은 주소가 여러 행에 있으면 첫 호출 결과를 재사용합니다.
- 이미 좌표가 있는 행은 API를 호출하지 않으므로, 재작업 시에는 남은 건만 빠르게 처리됩니다.

## 주소 파싱이 처리하는 패턴

`src/address.js`가 다음과 같이 공백 없이 붙어 있거나 지저분한 주소도 구조를 인식합니다 (자세한 배경은 `CHANGELOG.md` 참고).

- 번지 뒤에 시설명이 공백 없이 붙은 경우: `대화동1449-1송포공원`, `경의로790한산천`
- 한 필지에 번지가 콤마로 여러 개 나열된 경우: `주엽동3,142` (첫 번째 번지로 검색)
- 참고메모 괄호가 문자열 중간에 낀 경우: `종합운동장주변(민원)대화동2325-3`

그래도 못 잡는 새로운 패턴은 계속 나올 수 있습니다 — 그런 행은 조용히 틀린 좌표가 들어가는 게 아니라 지역 게이트와 검수 목록을 거치므로, 한 번 수동으로 확정하면 대체주소 사전에 남아 다음 회차부터는 자동으로 처리됩니다.
