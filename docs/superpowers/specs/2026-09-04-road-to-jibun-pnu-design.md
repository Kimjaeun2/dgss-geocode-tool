# 도로명 → 지번/PNU 변환 기능 설계

**작성일**: 2026-09-04
**대상**: `dgss-geocode-tool`
**상태**: 설계 확정, 구현 계획 대기

---

## 1. 배경

엑셀 대상지 목록 중 도로명주소는 정확하지만 지번주소 컬럼 값이 부정확하거나
모호한 경우가 있다. 지번주소를 사람이 일일이 다시 확인하는 대신, 신뢰할 수
있는 도로명주소를 기준으로 카카오 API를 통해 정확한 지번주소와 PNU(19자리
필지고유번호)를 뽑아 새 컬럼에 채워 넣는 기능을 추가한다.

기존 지오코딩 실행(`app.js` `startBtn` 흐름)은 좌표 확보가 목적이고, 지번주소
컬럼에 이미 값이 있으면 그 값을 우선 사용해 검색 쿼리로 쓴다
(`getAddress()`, `app.js:350`). 이 흐름은 그대로 둔다 — 지번 우선순위 로직을
바꾸는 것은 이번 범위가 아니다.

---

## 2. 범위

### 포함
- 별도 섹션/버튼으로 동작하는 "도로명 → 지번/PNU 변환" 기능
- 도로명주소 컬럼을 지정하면, 행마다 카카오 주소검색으로 지번주소 문자열과
  PNU를 뽑아 새 컬럼 2개에 기록
- 실패 건은 지도 보정 없이 단순 목록(주소 + 사유)으로 표시
- 결과를 별도 워크북으로 다운로드

### 제외
- 좌표(X, Y) 산출 — 이 기능의 목적이 아니다
- VWorld 프로바이더 사용 — 카카오 응답만으로 지번·PNU 조립에 충분하다
- 기존 지번주소 컬럼 덮어쓰기 — 새 컬럼에만 기록하고 원본은 그대로 둔다
- 기존 지오코딩 실행(`startBtn`)의 우선순위 로직 변경
- 지도 기반 수동 보정 UI — 실패 건은 텍스트 목록으로만 안내

---

## 3. 아키텍처

기존 도구와 마찬가지로 빌드 과정 없이 파일만 늘린다. 새 순수 함수 모듈
`src/pnu.js`를 추가하고, `app.js`에 독립된 섹션 하나를 배선한다.

```
index.html
  └─ 새 섹션: "도로명 → 지번/PNU 변환" (파일 업로드 이후, 기존 지오코딩
     단계들과 나란히 배치되되 별도 블록)
src/
  pnu.js      ← 카카오 address 객체 → PNU 조립 (순수 함수, API·DOM 비의존)
  app.js      ← 새 섹션의 이벤트 배선 추가 (기존 코드 옆에 추가, 기존 흐름은
                건드리지 않음)
tests/
  pnu.test.js ← pnu.js 단위 테스트
```

기존 `sheets` 전역 상태(업로드된 워크북의 시트 배열)를 재사용한다. 파일을
다시 업로드하게 하지 않는다.

### 3.1 PNU 조립 규칙 (`src/pnu.js`)

카카오 `geocoder.addressSearch()` 응답의 `result.address` 객체는 다음
필드를 이미 포함한다 (추가 API 호출 불필요):

| 필드 | 의미 | PNU 내 위치 |
|---|---|---|
| `b_code` | 법정동코드 10자리 | 1~10자리 |
| `mountain_yn` | 산 여부 ('0' 또는 '1') | 11자리 |
| `main_address_no` | 본번 (최대 4자리) | 12~15자리 (4자리 zero-pad) |
| `sub_address_no` | 부번 (최대 4자리, 없으면 '0') | 16~19자리 (4자리 zero-pad) |

```js
function buildPnu(addressObj) {
  if (!addressObj || !addressObj.b_code) return '';
  const mountain = addressObj.mountain_yn === '1' ? '1' : '0';
  const main = String(addressObj.main_address_no || '0').padStart(4, '0');
  const sub = String(addressObj.sub_address_no || '0').padStart(4, '0');
  return addressObj.b_code + mountain + main + sub;
}
```

`mountain_yn`은 카카오 문서상 `'0'`(대지) / `'1'`(산)로 온다 — `'Y'`/`'N'`
문자가 아니다. `main_address_no`/`sub_address_no`가 비어 있으면(지번이 없는
결과) PNU를 만들 수 없으므로 빈 문자열을 반환한다.

## 4. 데이터 흐름

```
사용자가 "도로명 → 지번/PNU 변환" 섹션에서 도로명주소 컬럼 선택
 │
 ▼
[변환 실행] 클릭
 │
 ├─ 선택된 시트들의 모든 행을 순회 (기존 sheets[] 재사용)
 │
 ├─ 행마다:
 │    도로명주소 값 정규화 (Addr.normalize)
 │    │
 │    ├─ 값이 없으면 건너뜀 (집계에서도 제외)
 │    │
 │    ▼
 │    Addr.addressVariants() 로 만든 변형을 순서대로
 │    kakao.geocoder.addressSearch() 시도 (기존 callKakaoWithRetry 재사용)
 │    │
 │    ├─ 성공 + result.address 있음
 │    │    ─► 지번컬럼 = result.address.address_name
 │    │       PNU컬럼  = buildPnu(result.address)
 │    │       (result.address 자체는 있는데 지번 문자열이 비어있는 극히
 │    │        드문 경우는 실패로 간주)
 │    │
 │    └─ 실패(전 변형 소진) 또는 result.address 없음
 │         ─► 실패 목록에 { 시트, 행, 원본 도로명주소, 사유 } 추가
 │            해당 행의 새 컬럼은 비워둠
 │
 ▼
진행률 표시 (기존 지오코딩 진행률 UI와 동일한 패턴, 별도 상태 변수 사용)
 │
 ▼
완료 후 실패 목록 렌더링 (텍스트 목록, 클릭 시 지도 없음)
 │
 ▼
[다운로드] 클릭 → 원본 시트 + 새 컬럼 2개가 붙은 별도 워크북 저장
   (기존 지오코딩 결과 다운로드와는 별개의 파일)
```

### 4.1 병렬 처리 및 오류 차단

기존 지오코딩 실행과 동일한 패턴을 재사용한다:
- `concurrency` 워커 방식으로 동시 처리 (기존 UI의 동시 처리 수 입력 재사용
  또는 고정값 6)
- 연속 API 오류 10회 시 전체 중단 (기존 `noteApiResult`/`ERROR_BREAKER_LIMIT`
  재사용) — 쿼터 소진이 대량 실패로 위장되는 것을 이 기능에서도 막는다
- 캐시: 같은 도로명주소가 여러 행에 있으면 첫 결과 재사용 (기존
  `geocodeCache`와 별개의 캐시 `Map`을 새로 둔다 — 이 기능의 결과 형태가
  다르므로 캐시를 공유하지 않는다)

## 5. 컬럼 매핑 & 출력

### 5.1 입력 컬럼 선택
- 새 섹션에 컬럼 선택 드롭다운 1개: "도로명주소 컬럼" (기존 컬럼 매핑 UI의
  `autoGuess` 로직 재사용해 "도로명주소" 헤더 자동 추정)
- 다중 시트 지원: 기존 흐름과 동일하게 헤더 이름 기준으로 선택된 모든 시트에
  적용 (`findOrCreateColumn` 재사용)

### 5.2 출력 컬럼
새 컬럼 2개를 도로명주소 컬럼 바로 뒤에 삽입한다 (기존 `reorderForOutput`과
동일한 패턴):

| 컬럼 | 내용 |
|---|---|
| `도로명기준지번` | 카카오가 돌려준 지번주소 문자열 |
| `PNU` | 조립된 19자리 필지고유번호 |

기존 지번주소 컬럼은 값·위치 모두 변경하지 않는다.

### 5.3 다운로드
기존 지오코딩 다운로드(`downloadBtn`)와는 별개의 버튼/파일로 만든다. 이
기능만 실행했을 수도 있고, 지오코딩과 같이 실행했을 수도 있으므로 두 결과를
섞지 않는다. 파일명: `원본파일명_지번PNU.xlsx`.

시트 구성은 기존 방식을 따른다: 원본 시트 뒤에 `_지번PNU` 접미어 시트를
붙인다 (시트명 31자 제한 처리는 기존 `doneSheetName` 로직 재사용).

## 6. 오류 처리

| 상황 | 처리 |
|---|---|
| 도로명주소 값 없음 | 건너뜀, 통계에서 제외 |
| 카카오 검색 전부 실패 | 실패 목록에 사유 `검색 결과 없음`으로 추가, 새 컬럼 비움 |
| 응답에 `address` 객체 없음 (도로명만 있고 지번 매핑 없는 특수 케이스) | 실패 목록에 사유 `지번 매핑 없음`으로 추가 |
| `b_code` 없어 PNU 조립 불가 | 지번주소는 채우고 PNU만 비움 + 실패 목록과는 별도로 "PNU 미확정" 경고 표시 |
| 연속 API 오류 10회 | 전체 중단 + 명시적 경고 (기존 로직 재사용) |
| 라이브러리 미로드 | 기존 시작 시 검사에 포함되어 있으므로 별도 처리 불필요 |

## 7. 테스트

`test.html`에서 함께 실행되는 순수 함수 테스트를 추가한다.

`tests/pnu.test.js`:
- `b_code` + `mountain_yn='0'` + 본번/부번 정상 → 19자리 PNU 조립 확인
- `mountain_yn='1'` (산) → 11번째 자리 `1` 확인
- `sub_address_no` 없음(단일 지번) → 부번 자리 `0000`
- `b_code` 없음 → 빈 문자열 반환
- 본번이 1~2자리인 경우 zero-pad 확인 (예: `'5'` → `'0005'`)

---

## 8. 구현 순서

1. `src/pnu.js` + `tests/pnu.test.js` — 순수 함수 먼저 확정 (API 없이 검증)
2. `index.html`에 새 섹션 마크업 추가 (컬럼 선택, 실행 버튼, 진행률, 실패
   목록, 다운로드 버튼)
3. `app.js`에 이벤트 배선 — 기존 카카오 호출/재시도/캐시/오류 차단 로직 재사용
4. 다운로드 로직 — 새 컬럼 삽입 + 별도 파일로 저장
